# ADR-0005: Steam depots through the Rust Steam crates with a DepotDownloader fallback

## Status

Accepted, 2026-10-28

## Context

A Rust-native path avoids a .NET runtime. A fallback de-risks protocol breakage.

## Decision

The primary path is `steamroom` for auth, product info, manifests, CDN, and the owned-license list. The license list is read on `steamroom`'s own connection through `recv_msg` for `EMsg::CLIENT_LICENSE_LIST`. Both were verified in the 0.3.0 source.

`steam-vent` is a fallback for the license list only. If used, it gets a fixed, distinct logon id so it cannot displace the in-prefix Steam client's session. applejack never opens a second concurrent Steam session for the same account by design.

The fallback is a pinned self-contained osx-arm64 DepotDownloader release. It runs as a separate process with a temporary data directory and no remembered password.

## Consequences

The project depends on `steamroom` and pins a DepotDownloader release. The fallback stays process-isolated.

Rejected alternatives.

- `steamcmd`. It is closed and has no QR login.
- The native macOS Steam client. It cannot be told to install Windows depots.
