# ADR-0002: Rust core exposed as a CLI and a stdio JSON-RPC server

## Status

Accepted, 2026-10-28

## Context

The SwiftUI shell needs to drive the Rust core. The project wants one notarizable helper executable and no FFI toolchain. The CLI doubles as the headless test surface.

## Decision

The Rust core is exposed as a CLI and a stdio JSON-RPC server. The SwiftUI shell spawns it and never links Rust directly. The CLI binary and the copy embedded in the app are the same build. Both are signed with the same Developer ID identity and the same explicit code-signing identifier `com.applejack.core`, set with `codesign --identifier`. Keychain items created by one are readable by the other. The installed CLI is a symlink to the app's embedded core.

## Consequences

Every shell feature goes through the JSON-RPC surface that the CLI also exposes. Ad-hoc development builds may prompt for Keychain access, which is acceptable in development.

Rejected alternatives.

- UniFFI. It adds a bindings toolchain and per-type glue.
- Tauri. The user chose SwiftUI.
