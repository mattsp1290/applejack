# ADR-0010: The Rosetta engine builds Wine from the WineHQ 11.0 stable release

## Status

Accepted, 2026-10-28

## Context

Gate G4a in the engine payload plan asks for one Wine source for the x86-64
Rosetta engine. No macOS build of a hardened, notarizable x86-64 Wine exists as
a reference. Two candidates were named: a WineHQ tagged release (Option A) and
the `apple/homebrew-apple` CrossOver-derived source that the Gcenx GPTK 3.0-x
builds reference (Option B). At the time of this record WineHQ offers 11.0 as
the newest stable release (January 2026) and 11.20 as the newest development
release. DXMT 0.80, the pinned MIT release, needs a Wine newer than 10.18.
`marzent/wine-msync` has not moved since August 2024 and targets Wine 9.x.

## Decision

Option A: Wine 11.0 from `https://dl.winehq.org/wine/source/11.0/wine-11.0.tar.xz`
(SHA-256 `c07a6857...` in `build/pins.toml`, matching WineHQ's signed
`sha512sums.asc`), built as x86-64 under Rosetta with
`--enable-archs=i386,x86_64`, `--with-mingw=llvm-mingw`, `--without-x`, and
`winemac.drv`. The stable branch is chosen over 11.x development releases
because it receives only fixes, which keeps the DXMT ABI (assumption A6) and
the hardened-runtime entitlement set (assumption A7) from moving between
payload builds. `--with-metal` does not exist at this tag; Wine detects Metal
in `configure.ac` on its own (see `docs/engines/payload-build.md`).

Option B stays the fallback: the `apple/homebrew-apple` Wine source at commit
`2bc4428` (the revision the Gcenx GPTK 3.0-x builds reference, recorded in the
plan's evidence on 2026-10-28), built the same way.

Trigger for Option B: gate G4e fails on Option A (a 32-bit PE or the Steam
bootstrapper does not run in the built Wine) and the failure is not fixed by a
patch recorded under `build/wine/patches/`, or gate G4d shows that D3DMetal
(assumption A5) loads only in a CrossOver-derived Wine and the user wants that
backend before the first release. Switching requires a new pin, a new revision
of this record, and a rerun of every G4 gate.

## Consequences

The payload advertises Wine 11.0 in `BUNDLE.toml`. The msync patch set is
applied only if it still applies cleanly at this tag (gate G4b); otherwise the
bundle advertises `["esync", "none"]`. Moving to a newer stable (12.0) is a
pin change plus a rerun of gates G4b through G4e.

Rejected alternatives.

- Wine 11.20 development release: newer fixes, but a moving ABI target for
  DXMT and for the entitlement spike.
- Wine 10.0 stable: older; DXMT 0.80 needs 10.18 or newer.
- Any Gcenx release asset: carries D3DMetal and is not a source build
  (ADR-0003, ADR-0004).
